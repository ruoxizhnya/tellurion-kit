# 0001 · 零业务概念

- **状态**：已裁决（来源：ADR-D29 §3.3 / QT-05）
- **场景**：原来 core 里有一堆"工具包"，其中混着 `strategy` 相关的辅助类型。拆仓时如果把"看起来通用"的都塞进 kit，kit 会在半年内长成第二个 core —— 所有仓都依赖它，于是任何业务改动都要动 kit。
- **决策**：kit 只收**纯技术能力**：日志、错误包装、ID、十进制、统计、HTTP 客户端/服务端、鉴权、可观测、时钟、沙箱、DB 连接。业务概念（backtest / strategy / order / factor / market）零容忍。
- **理由**：依赖图的底座必须稳定且无歧义。业务概念一旦进入底座，改一个词就影响全部仓，等于把"拆开"又缝回去。
- **代价 / 后果**：有些"半个业务"的工具（如交易日历工具）没地方放 —— 它们要么进 contracts（若跨边界），要么留在具体仓。接受这个摩擦，它逼我们想清楚归属。
- **替代关系**：无（本仓首条）
